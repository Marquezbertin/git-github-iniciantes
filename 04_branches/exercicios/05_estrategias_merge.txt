# Exercício 05 — Estratégias de Merge

## Dificuldade: Difícil 🔴

---

## 📋 Descrição

Praticar diferentes estratégias de merge: --no-ff, --squash e rebase antes do merge.

---

## 🎯 Objetivo

Saber escolher a melhor estratégia de merge para cada situação.

---

## 📝 Passo a passo

### Passo 1: Merge --no-ff (merge commit explícito)
```bash
mkdir merge-no-ff
cd merge-no-ff
git init

echo "Base" > app.txt
git add . && git commit -m "Base"

git checkout -b feature
echo "f1" >> app.txt
git add . && git commit -m "Feature 1"
echo "f2" >> app.txt
git add . && git commit -m "Feature 2"

git checkout main
git merge --no-ff feature -m "Merge feature no main"
git log --oneline --graph
```

### Passo 2: Merge --squash (juntar tudo em um)
```bash
cd ..
mkdir merge-squash
cd merge-squash
git init

echo "Base" > app.txt
git add . && git commit -m "Base"

git checkout -b feature
echo "f1" >> app.txt
git add . && git commit -m "Adicionar funcionalidade A"
echo "f2" >> app.txt
git add . && git commit -m "Correção de A"
echo "f3" >> app.txt
git add . && git commit -m "Finalizar A"

git checkout main
git merge --squash feature
git commit -m "Merge squash: adicionar funcionalidade A completa"
git log --oneline
```

### Passo 3: Comparar resultados
Crie `comparacao_merges.txt`:
```
=== COMPARAÇÃO DE ESTRATÉGIAS ===

--- NO-FF ---
Commits no histórico: [número]
Possui commit de merge: sim/não
Grandeza: preserva histórico completo da feature

--- SQUASH ---
Commits no histórico: [número (deve ser 1)]
Possui commit de merge: não (apenas 1 commit final)
Grandeza: história limpa e consolidada

Quando usar --no-ff: [situação]
Quando usar --squash: [situação]
```

---

## 🔍 Verificação

1. --no-ff criou commit de merge? ✅
2. --squash consolidou em um único commit? ✅
3. Os histórios são diferentes? ✅
4. Criou o arquivo de comparação? ✅
